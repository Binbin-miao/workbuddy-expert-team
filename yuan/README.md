# 源 (Yuan / `yuan`) v7.2

面向 WorkBuddy 的全栈自适应并发工程专家团：**1 主理官「天枢」+ 5 专职专家「璇玑 / 澄澈 / 浮光 / 玲珑 / 巧夺」**。

## v7.2 新增机制

1. **四态强制流转状态机**：`审讯对齐态 → Spec 落盘态 → 编码施工态 → 对照复审态`，严禁跳步。
2. **强制弹窗选择**：所有决策点必须走内置 `AskUserQuestion` 弹窗，严禁纯文本裸问；用户不拍板不写码。
3. **拍板即落盘 Spec / Tickets**：`/to-spec` → `/to-tickets` 产出 `SPEC.md` 与票单作为单一事实源，后续改动一律对照它做增量。
4. **改后对照 Spec 独立复审**：独立子代理不再只看 `git diff` 好不好看，还要核对「改动是否偏离 Spec」。

## 核心特性

1. **内置 Vibe Coding Grill-Me 核心执行协议（无需额外配置全局人设）**
   - **认知降维**：面向零代码基础决策者，自动将技术分支映射为 **「实际效果、工作量级、性能上限、交互颗粒度」** 四维直观对比。
   - **前置审讯阻断（零隐式假设）**：默认进入「审讯对齐态」，静默预检代码与高星开源方案后，通过三要素高信噪比提问收敛分支，用户拍板后方才动工。
   - **新发现必须重新过闸**：执行中若实测证据推翻用户此前选择，立即挂起重新上报，不得沿用过期决定。
2. **按需裁剪与三档子代理强度选配**
   - 严禁无脑全员出动，按任务领域仅挑选相关子代理，并在开工前提供 **1档（精简双人档）/ 2档（标准协同档）/ 3档（满血盲测档）** 供用户拍板。
3. **凡改必审铁律**
   - 无论代码由子代理编写还是主理官「天枢」亲自修改，只要产生 Diff，结单前强制派生独立子代理（「澄澈」或「巧夺」）执行 `>80%` 置信度差分审查，未过审严禁报完工。
4. **Git 与 PR 四步铁律**
   - 非要求不逐次 push → 本地原子 commit + `.patches/` 补丁归档 → 先上生产/真机验证 → 攒批 squash 成单一干净 commit 再推远端/提 PR。
5. **技能复用本机技能库，不覆盖任何已有技能**
   - 本包**不携带** `skills/` 目录。所有技能直接引用 `~/.workbuddy/skills/` 下的完整版，首次会话只做「就位检查」，缺失才提示，绝不静默批量覆盖。
